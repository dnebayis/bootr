# Security fixes, 2026-11-08

What changed after the review of 2026-11-06, which found no path to a private key but several ways a hostile creator
or an outsider could stall the platform or cost the owner money. The reviews in this folder are from 2026-10-27 and
describe the code before these changes; where a finding below is also in them, this note is the current status.
Every item has a test that failed before the change and passes after it.

## 1. CCIP-Read refused on every server-side chain client

A contract that reverts with `OffchainLookup` (ERC-3668) made a default viem client fetch the URLs the contract
named, as often as the contract kept reverting. The supervisor reads contracts creators chose, the web routes read a
signer's smart account, a locker and a launcher, the relay reads a payer-named asset. Every `createPublicClient` now
passes `ccipRead: false`: `apps/supervisor/src/chain.ts`, the shared `apps/web/lib/server/chain.ts` (used by the SIWE
check, the claim and the launch routes) and `apps/inference/src/reconcile.ts`. The indexer's own client
(`apps/indexer/src/lib/rpc.ts`) is imported by indexing code and therefore part of Ponder's build id; it was left as
it is (a change needs a new `DATABASE_SCHEMA`) and reads only Bootr's own contracts.

Tests: `apps/supervisor/test/ccip-read.test.ts`, `apps/web/lib/server/chain.test.ts` (a mock RPC answering every
`eth_call` with `OffchainLookup` pointing at a local gateway: a default client reaches the gateway, ours never does).

## 2. A ceiling on every agent tool call

Agents run one at a time, so one tool that never answered held every agent. `executeAction`
(`apps/supervisor/src/broker/index.ts`) cuts a call at `TOOL_READ_TIMEOUT_MS` (60 s, read tools) or `TOOL_TIMEOUT_MS`
(180 s, write and money tools): a read fails as `tool_timeout`, a write or money tool ends `unknown` and is settled
from receipts like any other unknown outcome. Test: `apps/supervisor/test/tool-timeout.test.ts`.

## 3. Bodies read under a cap; the launch image under the `read_url` host rules

`read_url` and the agent card fetch buffered a whole response before looking at its size; the agent API's image fetch
followed redirects anywhere and buffered the body. `@bootr/shared/public-fetch` now holds the public-host check and a
streaming reader with a byte cap (the body is cancelled at the cap), used by `apps/supervisor/src/web-reader.ts` (1 MB,
text marked truncated), `apps/supervisor/src/agent-card.ts` (256 KB, a larger card is unreadable; the coin reader and
onboarding read cards through it) and `apps/web/lib/server/image-fetch.ts` (2 MB, redirects followed by hand with the
host check on every hop, `accept-encoding: identity`). Tests: `apps/supervisor/test/response-bomb.test.ts`,
`apps/web/lib/server/image-fetch.test.ts` (a local server answering with a 256 MB gzip bomb; memory stays bounded).

Every container in `docker-compose.coolify.yml` has a `mem_limit` (5.5 GB of the CX33's 7.6 GB together), see
`docs/deploy/coolify.md` section 7. The supervisor's picture downloads (`images.ts`) were not in this change.

## 4. Sleeping agents cannot starve the tick

The tick took `MAX_AGENTS_PER_TICK` runtimes by `nextAt`, and a sleeping agent never moves its `nextAt`, so ten
sleeping coins filled every slot for good. Awake runtimes are selected apart from sleeping ones; sleeping runtimes get
a sweep of `MAX_SLEEPING_PER_TICK` (default `MAX_AGENTS_PER_TICK`, 0 = none), least recently checked first. The sleep
and wake rules are unchanged. Test: `apps/supervisor/test/tick-starvation.test.ts`.

## 5. A daily budget on X reads per agent

X bills the owner per post read; one agent's tools could run that up alone. Every read in the sender counts against
`SENDER_DEFAULT_READS_PER_DAY` (400 units per agent per UTC day, over what `sender_reads` already meters; 0 = no
budget; `apps/sender/src/read-budget.ts`). Thread walks stop at the budget, mention and timeline pages ask X for no
more posts than are left, the account activity check reads a page of five instead of a hundred, and an agent past the
budget gets `429 read_budget_exhausted` with `retryAt` at midnight UTC. The post quota is untouched. Test:
`apps/sender/test/read-budget.test.ts`.

## 6. The indexer's `/sql/*` route is gone

Ponder's SQL-over-HTTP client was public and no Bootr client used it. Ponder's own `/health`, `/ready`, `/metrics` and
`/status` are registered in front of the app and cannot be removed or guarded from the API code; they carry
operational counters and the chain head, no secrets. Guarding them would be a rule in Coolify's proxy, not done here.

## 7. The draft and nonce routes are bounded

`POST /api/launch/draft` takes 20 writes per minute per IP and `POST /api/agent/nonce` 30 calls (429 `rate_limited`,
`Retry-After`). The draft store holds at most 5,000 drafts (`store_full` for a new id past that) and a sweep started
by a draft write at most every ten minutes removes drafts that never launched a day after their last write, only once
a caught-up indexer (`/ready`) says no coin carries the id: a launched coin's agent card and contract URI read its
draft for good. `docs/agent-identity.md` "Storage and operations". Tests: `apps/web/lib/server/launch-drafts-sweep.test.ts`,
`apps/web/app/api/launch/draft/route.test.ts`, `apps/web/app/api/agent/nonce/route.test.ts`.

## 8. No RPC URL in a stored or logged error text

The tick put a viem error's full message, URL and key included, into `report.errors` (logged whole) and the runtime's
`last_error`. `rpcErrorText` (`apps/supervisor/src/log.ts`) stands in front of every stored or reported error text,
and the logger scrubs every field of every line, not only `err`. Test: `apps/supervisor/test/log-scrub.test.ts`.

`docker-compose.coolify.yml`: `ENABLE_MODE_BUNDLER_URL`, `ENABLE_MODE_PAYMASTER_URL`, `PAYMASTER_URL`,
`BASE_RPC_FALLBACK_URL`, `DEPLOYER_PRIVATE_KEY`, `PLATFORM_TREASURY_PRIVATE_KEY` and `BASESCAN_API_KEY` are dropped
from every service that does not declare them. There is no `LAUNCH_*` secret in the repo.

## 9. The platform account links only its own sites and its sources

The publish gate accepted any https link for the platform agent. `platform_link_forbidden`
(`packages/agent-core/src/social/post-validation.ts`, `PLATFORM_LINK_HOSTS`): bootr.fun, x.com, basescan.org,
clanker.world, dexscreener.com, their subdomains, and the source a post credits; bare domains X would link count too.
Coin agents are unchanged. Test: the "links in platform posts" cases in `post-validation.test.ts`.

## Still open

- Ponder's `/metrics` and `/status` stay public (item 6).
- The draft store cap is a bound, not a defence: 5,000 drafts from many addresses would hold new launches until the
  sweep clears the stale ones a day later.
- The X read budget is global (one default), not per agent.
- The indexer's RPC client has no `ccipRead: false` (item 1), pending the next schema bump.
